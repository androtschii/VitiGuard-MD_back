# Модели

Модели для `POST /api/v1/ai/diagnose`. Веса не хранятся в git: модели переобучаются, а каждая версия весит от 15 до 100 МБ.

| Файл | Что делает | Обязателен |
|---|---|---|
| `diagnosis.onnx` | классификатор болезней (EfficientNet-B0) с картой активации классов для тепловой карты | да: без него диагностика отвечает 503 |
| `lesion.onnx` | сегментация поражения (U-Net, энкодер ResNet-34) | нет: без него диагноз ставится без маски и степени поражения |
| `risk.onnx` | заражение милдью на следующий день (LightGBM, pr-076) | нет: без него окно риска показывает только агромодели |
| `vine.onnx` | стволы и грозди на фото ряда (YOLO11n, `ml/notebooks/vine_colab.ipynb`): `POST /api/v1/ai/vine/detect` и выкатка на робота | нет: без него распознавание лозы отвечает 503 |
| `diagnosis.gate.json` | отсев «не лист винограда» на признаках классификатора | нет: без него любой снимок получает диагноз (бумагу модель называла оидиумом) |

Рядом с каждой моделью лежит `.json` с тем же именем: название модели, размер входа и (для классификатора) порядок классов — порядок выходов сети. Описания хранятся в git и должны соответствовать весам.

## Как получить модели

1. Обучить модели в Google Colab ноутбуком `ml/notebooks/train_colab.ipynb` (или командой `python -m vitiguard_ml.experiments` на машине с GPU) и скачать веса из `results/models/` (`efficientnet_b0.pt`, `unet.pt`).
2. Экспортировать их для сервера из каталога `ml/`:

   ```bash
   uv sync --group train
   uv run python -m vitiguard_ml.export_server --weights <папка с весами> --out ../models
   ```

   Скрипт записывает `diagnosis.onnx`, `lesion.onnx` и их описания.

3. Обучить отсев «не лист винограда» (нужны картинки винограда, полевые фото и картинки «не винограда» — предметы и листья других культур):

   ```bash
   uv run --with onnx --with onnxruntime python -m vitiguard_ml.leaf_gate        --model ../models/diagnosis.onnx --grape <виноград> --field <полевые фото>        --not-grape <предметы> <листья других культур>
   ```

   Команда добавляет к `diagnosis.onnx` выход `features` и пишет `diagnosis.gate.json`. Отсев обучен на признаках конкретных весов: после нового экспорта модели его нужно обучить заново.

Пути к моделям задаются переменными `VITIGUARD_DIAGNOSIS_MODEL_PATH` и `VITIGUARD_LESION_MODEL_PATH`.

## Модель риска

Обучается на процессоре за минуты, GPU не нужен:

```bash
uv run python -m app.cli.risk_dataset --out ml/data/raw/risk   # архив погоды 2015-2025, около 15 минут
cd ml
uv run --group train python -m vitiguard_ml.risk.export_server --out ../models
```

Команда пишет `risk.onnx` и `risk.json`: порядок признаков, порог F1, качество на проверочном году и сверку ответов ONNX с LightGBM.

## Модель лозы

Обучается в Colab ноутбуком `ml/notebooks/vine_colab.ipynb`: версии и метрики на тестовой выборке пишутся в `Мой диск/vitiguard/vine/registry.json`. Новая версия принимается, если mAP50-95 выросла и ни один класс не упал больше чем на 1 пункт. Принятую модель скопировать как `models/vine.onnx`, а её версию и метрики записать в `models/vine.json`.

| Версия | Вход | Эпох | mAP50 | mAP50-95 | ствол | гроздь |
|---|---|---|---|---|---|---|
| v001 | 640 | 20 | 0,774 | 0,380 | 0,296 | 0,464 |
| v002 (на сервере) | 960 | 40 (дообучение v001) | 0,786 | 0,413 | 0,303 | 0,524 |
